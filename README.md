# 无错语言 WucuoLang (Wucuo)

**把"怎么写"交给语法，把"写什么"还给人脑。**

> 零心智负担语法（Zero-Mental-Cost Syntax）——一门"AI 写不错"的中文编程语言。
>
> 定位：**把代码"怎么写"的错清零**（类型/状态/副作用），让 AI 把脑力省下来记业务逻辑。
> 边界：**不防"写什么"的错**（业务逻辑错/外部依赖错）——那是人类的活儿，语言用强制兜底逼你审。
> 性能定位：**IO 密集型与逻辑编排**（GC 停顿影响小，性能稳定）——不是通用高性能语言。

## 为什么做这门语言

现在的编程语言（Python/Java/C++）都是给**人**设计的。当 AI 来写代码时，
语言的"宽松"就成了陷阱：

- 动态类型 → AI 经常类型混用，运行时才炸
- 变量默认可变 → AI 不小心改了不该改的状态
- 隐式转换 → `1 + "1"` 这种错 AI 天天犯
- 错误静默 → AI 忘了处理异常

**传统语言不是没有防错手段**（Java 有 Optional/异常体系，Python 有 mypy），
但它们的防错**靠程序员主动加代码**（判空、try-catch、类型注解）——AI 忘了加，错就漏过去。
无错语言把防错**做成语法默认行为**（默认不可变、纯函数隔离、操作强制兜底）——
不是"你得记得写"，而是"语法上写不出来错的"。

## 设计理念（蒸馏自 Fun / Fluxon / AIL）

1. **危险的事语法上做不到**（借鉴 AIL）——纯函数里打印直接编译报错
2. **一个任务一种写法**（借鉴 Fluxon）——循环只有一种，AI 没有选择就没有选择错误
3. **极小可读**（借鉴 Fun）——15 个中文关键字，一张参考卡让 AI 学会
4. **数字不骗人**（借鉴 Fun）——精确十进制，`0.1 + 0.2 == 0.3` 为真

## 快速开始

```bash
python wucuo.py examples/hello.wc       # 运行（解释器）
python wucuo.py --compile 程序.wc       # 运行（字节码编译，快4-7倍）
python wucuo.py --check 程序.wc         # 类型检查
python wucuo.py --repl                  # 交互模式
```

第一个程序：

```

```

## 语言特性

- **全中文关键字**：`量` `可变` `功能` `纯功能` `若` `循环` `对` `返回` `抛错` `捕获` `打印`
- **不可变默认**：`量` 声明的变量不可修改，杜绝意外改状态
- **强类型 + 自动推断**：类型错了编译期就报，不用写类型标注
- **零隐式转换**：`1 + "1"` 编译报错，必须 `转数字("1")`
- **纯函数强制**：`纯功能` 里禁止打印/抛错/副作用，解析器拒绝
- **操作函数强制兜底**：`操作` 声明副作用函数（调API/读写文件），普通/纯功能里调用必须 `捕获()` 包住——编译器逼你处理"外部世界会崩"
- **精确数字塔**：`0.1 + 0.2 == 0.3`，整数永不溢出
- **生成器**（轻量协程）：`协程()/恢复()/让出()`——yield 语义，可暂停/恢复/双向通信（暂无事件循环，非并发协程）
- **一种数据结构**：`{}` 既是对象也是数组
- **错误即值**：`捕获()` 返回 `{成功, 值, 错误}`，必须检查
- **死循环保护**：循环超过 100 万次自动拦截
- **默认参数**：`功能 f(a, b = 1)`，可不传
- **多返回值**：`量 a, b = 函数()` 解构赋值
- **键值对遍历**：`对 键, 值 在 表`
- **模块系统**：`导入("文件.wc")` 多文件编程
- **标准库**：文件读写 / JSON / HTTP 网络 / 字符串 / 列表 / 时间 / 随机 / 数学（60+ 内置函数）
- **FFI 架桥**：`导入Python("os")` 直接调用 Python 全生态（加密/图像/数据库/科学计算）

### ⚠️ 执行模式与 FFI 兼容性（重要！）

| 执行模式 | 导入Python | 说明 |
|---------|-----------|------|
| 解释器 | ✅ 支持 | 依赖系统 Python 环境 |
| 字节码 --compile | ✅ 支持 | 依赖系统 Python 环境 |
| **原生 C（build_c）** | ❌ **拒绝** | C exe 无 Python 运行时，编译时直接报错 |

> C 编译模式只支持纯 Wucuo 代码（内置函数 + 表 + 算术）。需要 Python 库时请用解释器/字节码模式。

## 防错示例（AI 常犯的错，全部被拦截）

```python
量 分数 = 80
分数 = 90
# ❌ 类型检查错误: 变量 '分数' 是不可变的。要修改请用 可变 声明

量 a = 10
打印(a + "个苹果")
# ❌ 类型检查错误: 运算符 + 需要两侧同类型。提示：用 转数字() 或 转文本()

纯功能 算(x) {
    打印(x)      # ❌ 纯功能里不能打印（副作用）
}
```


## 实现原理

```
源码 ──词法──▶ token ──递归下降──▶ AST ──类型检查(防错)──▶ 树遍历解释器
      lexer.py       parser.py        checker.py           interpreter.py
```

- 纯 Python 实现，零依赖，约 1500 行
- 类型检查在**执行前**完成，错误带修复提示
- 数字塔用 Python 的 Fraction 保证精确
